# 前提知識 []({#前提知識})

* 単位元	ある数と演算しても元の数が変わらない値のこと
* 左結合	左から計算した値を正しいとすること
* 右結合	右から計算した値を正しいとすること
* 積		いくつかの値を積んでおくこと（リストを構築すること）
* 余積		統合すること、適用すること
* 双対		\+と-など、逆の計算や操作を表すこと、積と余積も双対
* リテラル	対象とすることが出来る値の集まりのこと
* 関数		変化を記述するためのもの（動詞と同じ意味）
* 前置演算子	リテラルの前に置かれる演算子のこと
  （例）	\!5
* 中置演算子	リテラルとリテラルの間に置かれる演算子のこと
  （例）	1 \+ 2
* 後置演算子	リテラルの後ろに置かれる演算子のこと
  （例）	5\!
* 多項式	複数の演算子が使われている式のこと
  （例）	1 \+ 2 \* 3
* 二項演算	中置演算子一つだけで表される式のこと
  （例）	1 \+ 2
* 演算の組	特に、例のような二項演算の組といった説明がされる
  （例）	(1 \+ 2\) \* (3 \+ 4\)
* スコープ	演算時の状態変化を階層化し、お互いに干渉しないために必要
  		特にセキュリティのためにある

# 言語の特徴 []({#言語の特徴})

Signは、既存の言語とは慣習が違う言語である。
以下に特徴をまとめる。

* カッコの種類を問わず、カッコの意味は同じ
* 制御のために使われる単語（予約語）が存在しない
* 制御のための文（ステートメント）はなく、全ての計算は必ず答えを返す
* ブロック構文は、タブ文字によるインデントによって行われる
* 空白は演算子として考察するが、リテラルの区切りとして扱って良い
* 空白によって関数合成が行われる場合、それは左結合である。
* 前置演算子、及び後置演算子は対象となるリテラルとの間に空白を入れてはならない
* 中置演算子は前後に空白を必要とする
* リテラルだけで意味のない行が実行されることはない
* コードファイル単位でローカルスコープを持ち、importやexportをしない限り、スコープが汚染されることはない
* 空のリストと未評価なラムダ項はfalseである。他はtrueであるため、ブーリアンという型が明示されることはない
* 論理演算は基本的に短絡評価である
* ビット演算は最適化や低レイヤーのレジスタ操作のために用意されている。ビット演算を直接表す演算子群（`<<`, `>>`, `||`, `&&`, `;;`, `!!`）を使用可能である。
* 関数に渡された引数のリストは、リストである
* 計算すべき対象は、全てリストである
* Signのソースコードそのものも、リストである

# コメント []({#コメント})

Signは意味のないリテラルだけの行を実行することはない。
つまり、行頭から始まる文字列リテラルがコメントとなる。
行頭（インデントなし）から始まる ` であることが自明であるため、文字列を閉じなくても、その行全体がコメントとして扱われる。

逆に、タブでインデントされた状態から始まる \` や、行頭の空白（前の行の続き）の後の \` はコメントとはみなされず、通常の文字列リテラルとして評価される。
また、「行頭の \` は常にコメント」という絶対ルールがあるため、文字列リテラルから始まる式を行頭に書きたい場合は、コメント化を避けるために括弧 `()` でくくるか、変数にバインドする必要がある。

（例）
```javascript
`これはコメント`
`これはコメント

`	これはコメント`
`	これはコメント
	`これはコメントではない`
	`これはエラー

```

# リテラル []({#リテラル})

リテラルは、以下の通り。

* 数値
  * 符号なし整数
  * 符号あり整数
  * 浮動小数
  * 分数
  * 16進数
  * 8進数
  * 2進数
  * Register表現
  * Unicode
* 文字
* 文字列
* リスト
* 関数
* 構造体
* 識別子
* Unit

## 数値 []({#数値})

数値については、他の言語とほぼ同様。ただし、算術は浮動小数点演算として捉えられたほうが良いという思想はある。
その他の整数値やn進数については、システムを扱う場合にのみ限定されたほうが良いというねらい。
各書式は、以下の通り。

* 符号なし整数
  57

* 符号あり整数
  \-57
  57

* 浮動小数
  3537.45468
  0.357
  187.0235
  \-0.00357
  \-187.0235

* 16進数
  0xAF8534

* 8進数
  0o3574

* 2進数
  0b00101001

* Register表現
  `0r` に続く16進の数字（`0r18` など）は、レジスタに置く即値を16進で書いた数（`Int`）です。番地（`0x`）ではないので、番地をずらす数として使えます（`p + 0r18`）。64 ビットで回ります。

* Unicode
  0u3042

## 文字 []({#文字})

文字については、Signは独特のアプローチを取る。

* `\` の直後の任意の1文字は必ず文字として扱います。あらゆる記号（改行など）もそのルールに従う。改行は CRLF でも1文字と数え、`\` + 改行は文字の改行（U+000A）になって、次の行は同じ処理行の続きになります（[preprocessor.md](../impl/build/preprocessor.md) §0）
* 文字列リテラルの中に `\` が存在する場合は、`\` はそのまま文字列の中の1文字としての `\` となる

## 文字列 []({#文字列})

文字列についてのSignの振る舞いは以下のとおり。

* \` で挟まれた文字列が文字列

  （例）
  ```javascript
  `Hello World`
  ```
* 中に改行を含むことは出来ない
* 中に \\ を含めることが出来る

  （例）
  ```javascript
  `sign文字列は\を含めることが出来る`
  ```

## リスト []({#リスト})

リストは原則、リテラルを , で区切ったものである。

* 関数以外のリテラルであれば、空白（スペース）で区切ることも出来る
* リストは原則、タプルリストになる
* 文字のリストは文字列として扱う
* `__` は空のリストと同じ
* 区切りに使われる , は、積を作る演算子である。

## 関数 []({#関数})

関数の定義と評価方法についての概要は以下の通りです。（定義例や評価例の詳細は [ラムダ構築（?）](#　?-（ラムダ構築　中置演算子　※）) セクションを参照してください）

* **ラムダ構築子 (`?`) による定義**: 関数は原則、`?` 演算子で定義します。左辺に引数リスト、右辺に本体（式）を記述します。
  （例）
  ```javascript
  x y ? x + y
  ```
* **ポイントフリー（演算子の関数化）**: 全ての演算子は関数であり、ブラケット `[ ]` で囲むことで関数として扱えます。
  （例）
  ```javascript
  [+]
  ```
* **部分適用**: 引数の一部だけを適用した式も関数として扱われます。
  （例）
  ```javascript
  [+ 1]
  ```


## 構造体 []({#構造体})

連想配列の振る舞いは、通常のデータ構造をまとめただけのものである。詳細は以下の通り。

* 「key : value」の形式で記載する
* タブ文字によって階層化される
* keyは識別子か文字か文字列となる
* valueは、リテラルであれば何でも値とすることが出来る。

## 識別子 []({#識別子})

この言語には予約語が存在しないため、あらゆる言葉を識別子として使用可能である。詳細は以下の通り。

* `_` 一文字だけを識別子には出来ない
* 記号全般は識別子に出来ない
* 数字から始めることは出来ない
* `_`から開始することは出来る
* 全ての英数字を含めることは出来る
* Asciiコード以外の範囲での文字はすべて使える

## Unit []({#unit})

リストおよび関数の単位元。
普段はNullの意味で使われ、falseの意味でも使われることとなる。詳細は以下の通り。

* `__`で表される。
* `__` だけが評価された場合、当然`__`を返す。
* `__` は 単位律の象徴記号として成り立つため、第１引数を返す。

# 演算子 []({#演算子})

## `:`	（define　中置演算子　※） []({#　:-（define　中置演算子　※）})

defineがこの言語で最も優先順位が低い理由は、他の関数や演算を別の名前で定義するために使われるからである。
構文として入れ子が可能で、その場合は構造体となる。
defineは、常に以下の型となるため、通常の言語では代入演算子と同様のように捉えても良い。

`【識別子】 : 【式】`

（例　通常の定義について）
```javascript
nop : __
yep : !__
```

（例　構造体の定義）
```javascript
calc :
	additive :
		add : \+
		sub : \-
	multiply :
		mul : \*
		div : /
		mod : %
```

（例　手続き的合成の結果を保存したい場合）
```javascript

compositted_func : [* 2] [+ 3]

compositted_func2 :
	[* 2]
	[+ 3]

proc_result : [* 2] [+ 3] 5

proc_result2 :
	[* 2]
	[+ 3]
	5

```


## `#`	（output 中置演算子） []({#　#-（output中置演算子）})

具体的なIOアドレスやメモリアドレスを取ることも出来る。型としては以下の通り。

`【識別子 or 16進数】 # 【式】`

演算の結果は、Output成功時にはアドレス、失敗時にはUnitを返す。
これは、Inputの双対として整合するための仕様である。

（例）
```javascript
#stream : s ~t ?
	0xFF00 # s
	output t~
```

## ` `	（余積　中置演算子） []({#　-（余積　中置演算子）})
本言語における余積とは、**関数合成**、**関数適用**、**リストへ追加**、**リストの結合**に定まる。
空白でトークンを区切るという行為が、演算を表しているという仕様である。
ただし、余積は単なるトークンの区切りという理解で処理系のほうが合理的。
余積と積がキレイに対になる記述として覚えることが、この言語では大事。
複数の半角スペースは単一の半角スペースと同じ意味になる。
関数に関する余積は以下の型を取り、それぞれの挙動をその下に列挙する。

`【関数】 【式】`

`【識別子 → 関数】 【式】`

* 関数適用を表す。
* そのままの順番で関数合成される。（左結合である）
* 引数リストに渡す引数の羅列について明示する必要がある場合 , 中置演算子を用いる
* 以下の例では、比較演算子のほうが優先順位が高いため、カッコで優先順位を明示している

（例）
```javascript
[[+ 2] [* 5] 4] = 30
[[+] [* 2] 1 2 3 4] = 20
[[* 2,] [+] 1 2 3 4] = 20
```

## `?`	（ラムダ構築　中置演算子　※） []({#　?-（ラムダ構築　中置演算子　※）})

`?` はラムダ（無名関数）の構築を行います。
Signにおいて、ループや条件分岐などの制御構文はすべてラムダと代数的性質を組み合わせることで実現されるため、このセクションで豊富な定義例と評価例（結果値）を挙げて詳しく解説します。

---

### 1. ラムダ構築の基本

ラムダは `?` 演算子を使用し、`【引数リスト】 ? 【式】` の形式で定義します。

* **名前付き定義と評価**:
  定義したラムダ式を識別子にバインドします。
  ```javascript
  exp2fn : x y ? (x + y) ^ 2
  
  exp2fn 2 3  ` 評価結果: 25
  ```
* **名前なし（即時評価）定義と評価**:
  名前をつけずにラムダを使用する場合は、ラムダ式全体をカッコ `[ ]` で囲む必要があります。
  ```javascript
  [x y ? (x + y) ^ 2] 2 3  ` 評価結果: 25
  ```

---

### 2. 部分適用と Hole (`_`) / Unit (`__`) の挙動の違い

Signでは、ソースコード上に字句的に記述されるプレースホルダとしての **Hole (`_`)** と、実行時に流通する値としての **Unit (`__`)** が明確に区別されます。

* **プレースホルダ `_` による部分適用（コンパイル時静的脱糖）**:
  引数に `_` を直接記述すると、コンパイル時に自動的にその位置を引数とするラムダ式（クロージャ）へと変換されます。
  ```javascript
  add : x y ? x + y
  add_three : add 3 _   ` 静的脱糖: $p0 ? add 3 $p0 と等価
  
  add_three 5           ` 評価結果: 8
  ```
* **飽和・未飽和状態における `__` の挙動の違い**:
  実行時に渡される `__` は値として処理され、対象関数の引数の満たされ具合（アリティ）によって挙動が変わります。
  * **未飽和（引数がまだ足りない）状態での適用**:
    `__` は「墓標・吸収元」として機能し、Unit伝播を引き起こして式全体を `__` に崩壊させます。
    ```javascript
    add 3 __  ` 第一引数は 3 だが、第二引数に __ が渡されたため、アリティ未飽和の状態で Unit が伝播
              ` 評価結果: __
    ```
  * **飽和（引数がすべて満たされている）状態での適用**:
    `__` はコモナドの `extract`（評価の強制実行）として機能し、関数を直ちに実行します。
    ```javascript
    add 2 3 __  ` すべての引数（2と3）が揃っている状態で __ を適用したため、即時実行される
                ` 評価結果: 5
    ```


---

### 3. デフォルト引数とアリティ除外

仮引数リストをインデント（tabブロック）と `:` 演算子を用いて記述することで、デフォルト引数を有する関数を定義できます。

* **定義例**:
  ```javascript
  g :
  		x
  		y : x + 1
  		z : y + 1
  		~rest
  	? x y z rest~
  ```
* **アリティの除外と自動評価**:
  デフォルト引数はアリティ計算から除外されるため、デフォルト値を持たない必須引数（上記例では `x`）さえ渡せば、残りのプレースホルダや Unit を並べなくとも、自動的にデフォルト値が適用されて評価が実行されます。
  このとき、不足している実引数の末尾に対しては自動的に `__` (Unit) が暗黙のうちに補填されて呼び出されます。
  ```javascript
  g 3   ` x = 3 が渡され、y = 3+1 = 4, z = 4+1 = 5 となり、rest は空リスト（__）となる。
        ` (内部的には g 3 __ __ __ のように暗黙補填されて呼び出される)
        ` 評価結果: 3 4 5
  ```
* **暗黙のデフォルト引数適用 (フォールバック)**:
  動的な計算結果（例: 比較演算の偽）として `__` が算出され、それが引数として渡された場合、暗黙のうちにデフォルト値へとフォールバックして評価されます。
  省略されたパラメータ、または `__` が渡されたパラメータは、関数本体の評価開始時に自動的にそのデフォルト定義式へとフォールバックして解決されます。
  ```javascript
  g 1 (3 < 2)   ` 3 < 2 は偽（__）となるため、第二引数に __ が渡されたとみなされる。
                ` 第二引数が Unit のため、デフォルト値 y = 1+1 = 2 が適用される。
                ` 評価結果: 1 2 3
  ```

### 4. カッコ囲みの仮引数リストによるチルダ省略

仮引数リスト全体をカッコ（ブラケット `[ ]`）で囲んで定義した関数は、実引数として渡されたリストや構造体を、呼び出し側で後置チルダ `~`（展開）を付与することなく、そのまま直接受け取ることができます。
※参照が2つ以上ある場合でも、参照の数だけカッコを入れ子にすることで、参照の展開による境界を明示できます。
※もちろん、デフォルト引数やmatch_caseとの共存も可能です。

```javascript
` 仮引数リストをカッコで囲む
sum_list : [x ~xs] ? xs & x + sum_list xs | x

` 呼び出し側はチルダ（~）なしでリストを直接渡せる
sum_list [1 2 3 4 5]  ` 評価結果: 15

` デフォルト引数・match_caseとの共存例
func_mixed :
		[
			x
			y : x + 1
			~z
		]
	?
		x > 3 : x - y
		y

func_mixed [5]      ` 評価結果: -1 (x=5, y=6. x > 3 なので 5 - 6 = -1)
func_mixed [2]      ` 評価結果: 3  (x=2, y=3. x > 3 は偽(__)のため、y が評価される)
func_mixed [2 10]   ` 評価結果: 10 (x=2, y=10. x > 3 は偽(__)のため、y が評価される)
```

### 5. 構造体メンバーの一致による自動バインディング

仮引数リスト全体が `[ ]` で囲まれている関数に構造体を実引数として渡す際、構造体のメンバー名（キー）と関数の仮引数名が一致している場合、順番に関わらず自動的に名前ベースで分割代入（バインド）が行われます。
※参照が2つ以上ある場合でも、参照の数だけカッコを入れ子にすることで、参照の展開による境界を明示できます。
※もちろん、デフォルト引数やmatch_caseとの共存も可能で、Listの時の仮引数リストでの展開と同様の構文で定義できます。

```javascript
` 構造体を受け取る関数、~obj は必須ではないが、定義時に渡した構造体以下の構造体を保持したい場合に使う。
calc_diff : [foo bar ~obj] ? foo - bar

` メンバー名を一致させた構造体をそのまま（チルダなしで）渡す
calc_diff [
	bar : 20
	foo : 100
]
` 評価結果: 80 (位置に関わらず foo = 100, bar = 20 が自動で紐づく)

func_mixed :
		[
			foo
			bar : foo * 2
			~obj
		]
	?
		foo > 3 : foo - bar
		bar

func_mixed [
	foo : 4
]
` 評価結果: -4 (foo = 4, bar = 8。foo > 3 は真のため、foo - bar = 4 - 8 = -4 が評価される)
```

### 7. 再帰関数と短絡評価による終了条件

Signには `if` 文や `loop` 予約語は存在しません。Unit が論理値の「偽（False）」と同型であることを利用し、論理積 `&` や論理和 `|` の短絡評価（ショートサーキット）を用いて再帰の終了条件を定義します。

* **リストを反転する再帰関数**:
  ```javascript
  reverse : x ~y ? reverse y~, x
  
  reverse 1 2 3  ` 評価結果: 3, 2, 1
  ```
* **リストの長さを返す再帰関数**:
  ```javascript
  length : [x y ~z ?
  	y = __ : x
  	length x + 1, z~
  ] 0
  
  length 1, 2, 3  ` 評価結果: 3
  ```

### 8. ポイントフリースタイル（演算子の関数化）

演算子をブラケット `[ ]` で囲むことで、直接関数として扱うことができます。

* **単項演算子**: 前後に `_` をつけて表現します。
  ```javascript
  [!_] 2 < 3   ` 2 < 3 は真(2)。!2 は否定されて __ (Unit) となる
  [_!] 5       ` 階乗演算子となり、評価結果: 120
  ```
* **部分適用した演算子**:
  ```javascript
  [7 -] [* 5] 3  ` 3 に [* 5] が適用されて 15、さらに [7 -] に適用されて 7 - 15 = -8
                 ` 評価結果: -8
  ```

### 9. リストに対する自然変換（map/fold）と高階関数

ラムダを値として引数に渡す高階関数（mapやfold等）を扱う場合は、アドレス取得 `$` とデリファレンス `@` を組み合わせて参照渡しを行います。

* **自然変換 (map)**:
  部分適用したラムダの後ろに `,` 演算子を付与することで、リスト全体への適用を行います。
  ```javascript
  [+] 1 2 3 4     ` 左畳み込み（fold）と同等。評価結果: 10
  [* 2,] 1 2 3 4  ` マップ適用。評価結果: 2 4 6 8
  ```
* **高階関数の定義と評価**:
  ```sign
  map : f [h ~t] ? @f h  map f t

  ` 評価結果: [3 4 5 6]
  map $[+ 2] [1 2 3 4]
  ```

  ここで注意すべき点が2つある。

  **要素を並べるのは余積（空白）であって `,` ではない。** `,` は直積であり、
  スロットはスロットのまま中身へ再帰しない。`@f h , map f t` と書くと結果は
  `[3 [4 [5 [6]]]]` のように入れ子になる。Lisp の `cons` のつもりで `,` を
  再帰に使うと必ずこうなる（`,` 節を参照）。

  **リストを畳む再帰はブラケット分解（`[h ~t]`）で書く。** 上の例に終端条件が
  無いのは、リストが尽きた時点で `t` が `__` になり、それを受け取った呼び出しが
  完全性公理（`f __ = __`）で潰れるためである。裸の rest（`f ~xs`）は rest が
  何個でも吸うので呼び出しが常に飽和してしまい、完全性公理が終端を与えられない
  ——独自の終端条件を書く羽目になり、[原理5](../impl/0_design_principles.md)に反する。


## `,`	（積　中置演算子　※） []({#　,-（積　中置演算子　※）})

`,`は積を表す演算子であり、リストの定義を行うために使われる。
関数以外を空白で区切った場合、積と余積が一意に対応する。
よって、評価結果がリストの構築になる。
積演算子は以下の型を取る。

`【リテラル】 , 【式】`

（例）
```sign
1 , 2 , 3
```

### `,` は cons ではない

`,` は直積であり、**スロットはスロットのまま、中身へは再帰しない**。
リストを伸ばすのは余積（空白）の仕事である。

```sign
` スカラーの連鎖は平坦。余積と等価だから（list_model.md §2.1）
1 , 2 , 3          ` [1 2 3]

` 片側がリストなら2スロットの積になる。中身は展開されない
1 , [2 3]          ` [1 [2 3]]
```

この違いは再帰で効く。`x , 再帰呼び出し` と書くと、Lisp の `cons` のつもりでも
結果は入れ子になる。要素を並べたいなら余積（空白）を使うこと。

### 引数リストとして渡す

関数を即時に使わない場合、`,` で組み立てた積をそのまま引数リストとして渡せる。
受け取る側はブラケット仮引数（`[a b]`）で分解する——ブラケットは**渡された1個の
実引数をその場で分割代入する**宣言であり、積とリストのどちらでも同じ経路を通る。

```sign
F : [f ~xs] ? @f (xs ' 0)

F ($[* 2] , 1 , 2 , 3)     ` 2
```

**カッコが要る。** `,`（優先順位9）は空白（優先順位10）より弱いため、
`F $[* 2] , 1 , 2 , 3` は `(F $[* 2]) , 1 , 2 , 3` に切れてしまい、
積が `F` の引数として届かない。引数の区切りは空白の役目であり、`,` はあくまで
「1個の積を組み立てる」ためのものである。

ラムダを渡すときに `$` を付ける理由は[型システム仕様 §3.5](../impl/type/type_system.md)を参照
（同じ余積列に Lambda が並ぶと関数合成に解決されてしまうため、`$` で Address へ降格する）。

## ` `	（余積　中置演算子） []({#　-（余積　中置演算子）})
本言語における余積とは、**関数合成**、**関数適用**、**リストへ追加**、**リストの結合**に定まる。
空白でトークンを区切るという行為が、演算を表しているという仕様である。
ただし、余積は単なるトークンの区切りという理解で処理系のほうが合理的。
余積と積がキレイに対になる記述として覚えることが、この言語では大事。
複数の半角スペースは単一の半角スペースと同じ意味になる。
リスト操作の余積は以下の型を取り、それぞれの挙動をその下に列挙する。

`【関数以外】 【式】`

`【識別子 → 関数以外】 【式】`

* 関数以外であれば何でもリスト化する。
* 文字列やタプルリストを結合する。
* 構造体の結合も可能だが、値の上書きに注意
* **関数適用（apply）とリスト/構造体結合（concat）の優先度順位**:
  リスト（`[1 2]`）や構造体（`[foo: 10]`）は、ともに同じ直積（コレクション）として分類されます。
  余積の解決順序においては、リスト/構造体同士の連接（`concat`）の優先度が、関数への適用（`apply`）よりも低く設定されています。
  これにより、`f [1 2] [3 4]` や `f [foo: 10] [bar: 20]` のように引数を並べた呼び出しは、勝手に結合されて1つのリストになることなく、正常に `f` に対する別々の実引数として順番に適用されます。
  もしリストや構造体を明示的に結合させたい場合は、`[1 2]~ [3 4]~` のように双方に後置チルダ `~`（スプレッド）を付与して境界を明示する必要があります。

（例）
```javascript
[1 2 3] = 1,2,3
(1 2 3 , 4 5 6) [7 8 9] = 1 2 3 , 4 5 6 , 7 8 9
` スペースは余積（同じ次元で伸ばす）、カンマは直積（次元を上げる）
[1 2 3]~ [4 5 6]~ = 1 2 3 4 5 6 = [1,2,3,4,5,6]

`hello` \  `world!` = `hello world!`

sign : `Sign!`
hello : `Hello ` 
hello sign = `Hello Sign!`
```

## `~`	（範囲リスト構築　中置演算子） []({#　~-（範囲リスト構築　中置演算子）})

`~`は、前置、後置、中置で意味が異なる点に注意！
`~`中置演算子は、前後をカッコで囲む必要がある！
`~`中置演算子は、範囲を取り扱うことが出来る。型は以下の通り。

`【文字】 ~ 【文字】`
`【数値】 ~ 【数値】`
`【アドレス】 ~ 【アドレス】`


範囲リスト構築の演算子は、優先順位が低いので要注意。
リストから特定の範囲を取得する場合にも使いやすい。

（例）
```javascript
[1 ~ 10]
[* 2,] [1 ~ 10] ‘ [3 ~ 5] = 8 , 10 , 12
[\a ~ \z]
```

なお、ステップ値を持たせる等差数列や等比数列の構築には、算術演算子と組み合わせた派生演算子（`~+`, `~-`, `~*`, `~/`, `~^`）を使用する。
現在は「初期値 演算子 次の値 演算子 終端値」の**3項セット**で記述された場合のみ、正格評価されて実体のリストが構築も可能となる。

（例）
```javascript
[2 ~+ 2 ~ 10] = [ 2, 4, 6, 8, 10 ]
[1 ~* 2 ~ 16] = [ 1, 2, 4, 8, 16 ]
```
※本実装（ネイティブコンパイラ）では、遅延評価ジェネレータとしての二項対応（無限リスト等）も実装予定である。

`;`は、排他的論理和のための中置演算子である。

この演算子は、あくまで論理演算である。
論理演算は、全て短絡評価となる。

## `==` および `!==`	（equal　中置演算子） []({#　==　（equal　中置演算子）})

ここからは、具体的な比較演算子の説明となる。
`==` は構造比較専用の演算子であり、List・Structなどの構造を対象とする。
`=` とは別演算子・別優先順位であり、機能を混同しないこと。
`!==` は `==` の否定（構造内で等しくないなら真）である。

## `<`	（less　中置演算子） []({#　<-（less　中置演算子）})

`==`/`!==` を除く比較演算子（`<`, `<=`, `=`, `>=`, `>`, `!=`）は、条件が真のときに特定の値を返し、偽のときに `__` (Unit) を返します。これにより、数学的かつ直感的な比較演算の連鎖（Chaining）を無矛盾に表現・評価します。

### 比較演算の値返却規則（値ベースの代数的ルール）
比較演算子（`<` など）に左辺（LHS）と右辺（RHS）を適用した際、真の場合に返却される値は**左辺の評価値**に基づいて決定されます。
- **左辺が単位元である場合**: 左辺値が `0`（加法単位元）または `1`（乗算単位元）である場合、**右辺（RHS）の値**を返します。
- **左辺が非単位元である場合**: それ以外（`__` を含む）の場合、**左辺（LHS）の値**を返します。

### 連鎖比較（三項比較など）の評価フロー（ChainCompare）

比較演算子を `a < b < c` のように連鎖させた場合、二項演算の左結合（`(a < b) < c`）としては評価されません。
構文解析（パーサー）の段階で**特別な連鎖構文（ASTノード `ChainCompare`）として解釈**され、以下のルールで評価されます。

* **構文の制約**: 3項以上の比較になる場合、**同一の比較演算子の連鎖のみが許容**されます（例: `A < B < C` や `A <= B <= C` は可。`A < B > C` は構文エラー）。
* **評価ルール**:
  1. 連鎖するすべての隣接ペア（例: `a < b` と `b < c`）を評価します。
  2. 全ての比較が「真」である場合、**無条件で中央の項の値を返します**。
  3. いずれかの比較が「偽」である場合、即座に `__`（Unit）を返します。

これにより、`1 < x < 10`（x = 5 の場合）は以下のように評価されます：
- `ChainCompare(1, <, 5, <, 10)` として解釈される。
- `(1 < 5)` は真、`(5 < 10)` は真。全条件が真のため、中央の項 `5` を無条件で返す。式全体の結果は `5` となります。
- `4 < 10 < 5` の場合、`(4 < 10)` は真だが `(10 < 5)` は偽となるため、即座に `__` を返します。

この ChainCompare 方式は、二項比較（§「比較演算の値返却規則」参照）の指示的意味論（参照透明性）を完全に維持しつつ、「比較連鎖では中央の変数項を抽出したい」という直感的な挙動を両立するために採用されています。単項の単位元ルール（`{0, 1}` の判定）は、あくまで2項比較（連鎖でない場合）にのみ適用されます（`__` は単位元判定の対象外であり、左辺値として扱われます）。

less は、左のほうが小さければ真になり、偽なら `__` を返します。

## `'`	（get　中置演算子） []({#　’-（get　中置演算子）})

`'`中置演算子は、対象から特定の値を得る。該当する値がなければUnitを返す。
なお、後ろに : 中置演算子をつけることで、対象の値を書き換える事が可能。
型は以下の通り。

`【構造体 or リスト or 文字列】 ' 【識別子 or 文字列 or 数値】`
`【識別子 → 構造体 or リスト or 文字列】 ' 【識別子 or 文字列 or 数値】`

（例１　変えない場合）
```javascript
car :
	brand : `Foo`, `Bar`, `Baz`

car ' brand ' 0
```
（例２　変える場合）
```javascript
car :
	brand : `foo`, `Bar`, `Baz`

car ' brand ' 0 : `Foo`
```

### 鍵の字面が読みを決める

印の無い鍵は左辺が決める——構造体なら名前、リストや文字列なら添字である。だがそれだけだと
`【対象】 ' ident` を読んでも**名前で引くのか中身で引くのか分からない**。左辺の型を知らないと
決まらないので、**鍵に印を付ければ字面だけで決まる**ようにしてある。

| 鍵の字面 | 読み | 例 |
|---|---|---|
| 識別子・式に後置 `~` | その**中身**を鍵にする（構造体なら名前、器なら添字） | `car ' k~`・`brand ' i~` |
| 前置 `@` | 同じ射。**単値のときだけ**書ける | `brand ' @i` |
| 固定値に後置 `~` | 中身は自分自身なので「撒く」＝そこから後ろ | `brand ' 1~` |
| 後置 `~` が2つ | 中身を取ってから撒く＝その位置から後ろ | `brand ' i~~` |
| 印なし | 左辺が決める（上の型） | `car ' brand`・`brand ' 0` |

`~` はどの位置でも「中身を出す」で変わらない。変わるのは**何の中身か**であって、固定値の中身は
自分自身だから「中身を取る」が恒等になり、撒く読みしか残らない。2つ目の `~` がその「撒く」である。

（例３　鍵に印を付ける場合）
```javascript
car :
	brand : `Foo`, `Bar`, `Baz`
k : `brand`
i : 1

car ' brand ' 0        ` 評価結果: Foo              印なし。添字 0
car ' k~               ` 評価結果: [Foo Bar Baz]    k の中身（brand）を名前として引く
car ' brand ' i~       ` 評価結果: Bar              i の中身（1）を添字として引く
car ' brand ' @i       ` 評価結果: Bar              同じ射。単値なので前置でも書ける
car ' brand ' 1~       ` 評価結果: [Bar Baz]        固定値なので「撒く」だけ
car ' brand ' i~~      ` 評価結果: [Bar Baz]        中身を取ってから撒く
```

**構造体を実行時の鍵で引くときは必ず `car ' k~` と書く。** 前置 `@` を向けると断る
——構造体の物理配置は名前順なので、連番の綴りである `@` とは当たらないためである。名前付き
スロットに順序は無いので、`car ' k~~` は `car ' k~` と同じ値になる（撒く先が引いた値しかない）。

```javascript
car ' @k   ` エラー: 名前付きスロットへ前置 @ では引けません（鍵の中身で引くなら car ' k~）
```

## `@`	（get　中置演算子　※） []({#　@（get　中置演算子　※）})

`@`中置演算子は、特定の値を対象から得るので、`'`の右結合バージョンである。
なぜ、右結合と左結合がそれぞれ存在するかは、import時の記述が統一されるため。
該当する値がなければUnitを返す。
型は以下の通り。

`【識別子 or 文字列 or 数値】 @ 【構造体 orリスト or 文字列】`
`【識別子 or 文字列 or 数値】 @ 【識別子 → 構造体 or リスト or 文字列】`

（例）
```javascript
car :
	brand : `Foo`, `Bar`, `Baz`

0 @ brand @ car
```

`'` とは結合の向きが逆なので、括らずに1つの連なりへ `'` と混ぜることはできない（構文エラー、[`operator_table.md`](../impl/syntax/operator_table.md)）。`brand @ car ' 0` ではなく、`(brand @ car) ' 0` のように括って順序を書くか、`car ' brand ' 0` のようにどちらかの綴りに揃える。

**鍵（左辺）の印も `'` と同じである。** `1~ @ l` は切り出し、`i~ @ l` は `i` の中身で1つ引く、`i~~ @ l` は中身を取ってから撒く——向きが違うだけで規則は1つで、内部では `'` の形へ正規化される（`'` の節の「鍵の字面が読みを決める」）。

## ビット演算子群 （`<<`, `>>`, `||`, `&&`, `;;`, `!!`） []({#　ビット演算子群})

ネイティブコンパイル時の最適化や、低レイヤーのレジスタ操作・SIMD命令へのマッピングを前提としたビット単位の演算子である。

* `<<` : ビット左シフト（中置演算子）
* `>>` : ビット右シフト（中置演算子）
* `||` : ビット論理和（中置演算子）
* `&&` : ビット論理積（中置演算子）
* `;;` : ビット排他的論理和（中置演算子）
* `!!` : ビット反転（前置演算子）

## `!`	（階乗　後置演算子） []({#　!-（階乗　後置演算子）})

階乗は後置演算子となっている。
単純にシンタックスシュガーで実現する。

（例　答えはいずれも120）
```javascript

[*] [1 ~ 5]
1 * 2 * 3 * 4 * 5
```
## `~`	（平坦化 / 評価の強制　後置演算子） []({#　~-（平坦化　後置演算子）})

`~` は、前置、後置、中置で意味が異なる点に注意！

`~` 後置演算子は、主に**「リストの平坦化（Flatten）」**および**「評価の強制」**を行う。
多次元リストやネストされた構造を一段階フラットな状態に展開する作用と、Pullベースの遅延評価パラダイムにおいて値の確定（実体化）を強制するトリガーとして機能する。型は以下の通り。

【リスト or 構造体 or 文字列】\~
【識別子 → リスト or 構造体 or 文字列】\~

（例１　引数を渡すときに使う場合）
```javascript
a : 1 2 3 4 5
f : x y z ? z

f a~
```

（例２　残余引数リストの展開）
```javascript
a : 1 2 3 4 5
reverse : x ~y ? reverse y~, x

reverse a~
```

（例３　インポートと一緒に使う）
```javascript
IO@~
say `hello!`
```

### 鍵の位置の後置 `~`

`'` の右辺（中置 `@` なら左辺）＝**鍵の位置**でも、`~` の意味は「中身を出す」のまま変わらない。
変わるのは**何の中身か**である。

- **識別子・式に付いた `~` は、その中身を鍵にする**。`l ' i~` は「`i` が持っている値を添字にして
  1つ引く」であって、切り出しではない。前置 `@` を鍵に付けた `l ' @i` と同じ射である。
- **固定値に付いた `~` は切り出しになる**。固定値の中身は自分自身なので「中身を取る」が恒等に
  なってしまい、撒く読みしか残らないためである。`l ' 1~` は「1 番目から後ろ」。
- **`~` を2つ重ねると、中身を取ってから撒く**。`l ' i~~` は「`i` の中身の位置から後ろ」で、
  識別子で切り出したいときはこの綴りになる。

```javascript
l : 10 20 30
i : 1

l ' i~     ` 評価結果: 20         i の中身（1）を添字にして1つ引く
l ' 1~     ` 評価結果: [20 30]    固定値なので切り出し
l ' i~~    ` 評価結果: [20 30]    中身を取ってから撒く
```

構造体の鍵も同じ規則である。`s ' k~` は `k` の中身を名前として引く（詳しくは `'` の節）。

## `~`	（連続リスト構築　前置演算子） []({#　~　（連続リスト構築　前置演算子）})

`~`は、前置、後置、中置で意味が異なる点に注意！

`~`前置演算子は、「引数リストの残りを、一つ上のスコープのリストに閉じ込める。」と考えると良い。

型は以下の通り。

`~【識別子】 ? 【式】`

（例１　冒頭以外の残りをリストとして返す関数）
```javascript
tail : x ~y ? y
```
（例２　リストの長さを返す関数を、\~ 後置演算子と一緒に使って書く）
```javascript
length : [x y ~z ?
	y = __ : x
	length x + 1, z~
] 0
```

## `!`	（not　前置演算子） []({#　!　（not　前置演算子）})

`!` は、否定のための前置演算子である。
`!` の後置演算子は階乗となるので、区別してほしい。
この演算子は、あくまで論理演算である。
論理演算は、全て短絡評価となる。

## `$`	（アドレス取得　前置演算子） []({#　$　（アドレス取得　前置演算子）})
ある識別子の値の保持を行っているアドレスを返す。
型は、以下の通り。

`$【識別子】`

3つの境界演算子（`$`, `@`, `#`）のチェーンにより、値空間（スタック）と位置空間（レジスタ・メモリ）を跨ぐ「ハイブリッドマシン」を直接制御します。すべての低レベル駆動命令やレジスタ間接参照は、これら3つの演算子の組み合わせに還元されます。
* **`$`** : 値空間（スタック）から位置空間への参照の生成
* **`@`** : 位置空間から値空間へのデータの引き込み（インプット）
* **`#`** : 位置空間への書き込み・代入（アウトプット）

例
```
i : `hello`
@$i = i
@$i = `hello`

`つまり@$はID（何もしないのと同意だが、@$は内包値に対する自己関手とも言える）
@$ = __

`逆向きの演算はiがhexでないため、解なし
@i = __
$@i = __
```

### 任意のLambdaと `$Lambda` の真偽値評価
未適用のラムダ（Lambda）自体は、その単位元（射 `id` / `_`）との同一性により、論理評価された場合は `false` (falsy) と判定されます。
しかし、前置演算子 `$` を用いて `$Lambda` とすることで、ラムダ自体を `Implicit(Lambda)` 型のインスタンスとして参照化（カプセル化）できます。

実体化されたインスタンス（存在）である `$Lambda` は常に `true` (truthy) と評価されます。

これを利用して、「オプションのハンドラが存在すれば適用し、なければデフォルトを適用する」というフォールバック処理を以下のように自然に記述できます：
```sign
result : [$custom_handler | default_handler] args
```
```
a : 0x8000
a # 0xF000

`ダブルポインタが成立
@a # `hello`

`演算の確認
$@a = 0xF000
@$a = 0x8000
@$a  = a

`ダブルポインタ成立の確認（演算子の順番について、随伴関手定理に従っている）
@@$a = @a
@$@a = @a
```

## `@`	（import　後置演算子） []({#　@　（import　前置演算子）})

`@`後置演算子は、ファイルやライブラリをインポートする際に使われる。型は以下の通り。

## `↵`	（評価　後置演算子） []({#（評価　後置演算子）})

評価演算子は、処理系としてはトークンのまとまりを行として区切るものと同じ意味。よって改行を用いる。
改行とはつまり、その行を評価して良いという演算子に他ならないという見方も可能なだけである。
次の行が空白か、§0 に挙げた中置演算子で始まるなら、その改行は評価の区切りではなく続きである（`1 +` の次の ` 1` は `1 + 1`。[`preprocessor.md`](../impl/build/preprocessor.md) §0）。


## ブロック構築について []({#　ブロック構築について})

ブロック構築　前置演算子は、インデントによるブロックの構築となる。

（例　タブのあとの改行がカッコで括られた中の式と同じになる）
```javascript
[x y ?
	x = y = __ & `Nothing` |
	x + y
]

[x y ? [[x = y = __ & `Nothing`] | [x + y]]]
```
以下、カッコによるインラインブロックの構築も同じ意味であるため省略する。

# `"..."`の中の記述について。

対象とするバックエンド言語をインラインに記述する機能とする。

```sign
result : "
   mov     eax, 1
   add     eax, 2
   mov     eax, [ebx]
"
```

### 左辺優先キャスト規則の厳密化（算術逸脱時の退化規則）
Signはすべてのデータを型アグノスティックなリスト（Word）として扱うため、従来の静的な型エラー状態を保持しません。二項演算においては「左辺の演算子が全体の解釈ドメインを決定する」という左辺優先キャストが適用されます。
ただし、左辺が文字列である `` `123` + 0 + 57 `` のように、数値演算の解釈ドメインから適用データが完全に逸脱した場合は、暗黙の変換や例外的な型エラーを発生させず、一律で解決不能を示す **Unit (`__`) に退化** させます。
※現状、バックエンドの仕様により挙動が異なります。
