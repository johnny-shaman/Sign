# Sign 文字列リテラルとコメント構文

## 概要

Sign の文字列は必ずバッククォート（`` ` ``）で囲む。
行頭のバッククォートがコメントを開くのか式を開くのかは、**先読みルール**が決める（§2）。

---

## 1. 文字列リテラル

### 定義

```
string = ` [^\n\r`]* `
```

開始と終了をバッククォートで挟んだ、改行（`\n`/`\r`）とバッククォート自身を除く任意の文字列。

```sign
` greeting に文字列を束縛
greeting : `Hello, World!`
message  : `Sign is elegant`
```

### 特性

- 文字列はシングルライン（改行を含まない）
- 空文字列は `__`（Unit）と同型
- 文字列中にバッククォートは含められない（コメント開始と区別できないため）

---

## 2. コメント構文

### 定義（先読みルール）

```
comment = SOL ` !([^\n\r`]* ` [@~! ]) [^\n\r]* EOL   ← 行頭 ` は原則すべてコメント
string  =     ` [^\n\r`]* `                          ← 行頭以外は常に文字列リテラル
```

> [!IMPORTANT]
> **先読みルール**：**行頭のバッククォートは、閉じの直後が後置演算子（`@` `~` `!`）か
> 空白のときだけ式になる。** それ以外はすべてコメントである。
>
> - **閉じない** → コメント（EOL まで）
> - **閉じるが、直後が後置演算子でも空白でもない** → コメント
> - **閉じて、直後が後置演算子か空白** → 式（その行は文字列から始まる式である）
>
> 行頭以外のバッククォートは常に文字列リテラルであり、この規則は関与しない。

```text
`これはコメント（閉じなし）
`これもコメント`             ← 閉じても、直後が EOL ならコメント
`ここで `x` を引用する`       ← 閉じの直後が `x` → コメント（引用が書ける）
`main.sn`@~                ← 閉じの直後が後置 `@` → 式（インポートパス）
`Hello, ` name             ← 閉じの直後が空白 → 式（段10 の余積で連結）
x : `Hello`                ← 行頭ではない → 文字列リテラル
```

### なぜ「後置演算子か空白」なのか

**行頭から文字列で始まる式は、インポートか連結しかない。**
インポートは閉じの直後に後置 `@` が密着し、連結は空白——段10 の余積演算子——で続く。
どちらも閉じの直後に来るのは**演算子**である。これが判定の根拠になる。

散文の側では、最初の閉じバッククォートの直後は**引用したい中身**であって空白ではない
（`` `ここで `x` を引用する` `` の最初の閉じの直後は `x`）。だから両者は静的に分かれる。

> [!NOTE]
> **判別子は2度狭められている。**
>
> 1. 最初は「同じ行に閉じがあるか」だけで見ていた。インポートパスを行頭に書くための
>    規則だが、そのために `` `説明` `` のように**閉じたコメントがすべて文字列リテラルに
>    なり**、コメント中にバッククォートを書くと構文エラーになった。
> 2. 次に「閉じたうえで後続があるか」にした。閉じたコメントはコメントに戻ったが、
>    `` `ここで `x` を引用する` `` はまだ式に落ちる（閉じの後に後続がある）ため、
>    コメントの中でコードを引用できないままだった。
> 3. いまは「閉じの直後が演算子か」で見る。**言語の構文を説明するのがコメントの仕事で
>    ある以上、その構文を引用できないのは実際に困る**——これで3つが同時に解ける。
>    インポートは通り、閉じたコメントはコメントであり、コメントの中に引用が書ける。

> [!WARNING]
> **書けない形がひとつだけ残る。** 最初の閉じバッククォートの直後が空白である散文は、
> 連結の式として読まれて構文エラーになる：
>
> ```text
> `ここに ` がある      ← 最初の閉じの直後が空白 → 式として読まれ、エラー
> ```
>
> 空白を閉じの外に出せば通る（`` `ここに` がある ``）。**黙って別物になるのではなく
> エラーになる**ので、原理4（静的に検出できる違反は黙って別物にせず弾く）は保たれている。

> [!WARNING]
> **ファイルの最終行だけは、この判定が返り値を左右する。**
>
> ファイルスコープが返すのは最後の式であり、そこに文字列を書けばその文字列が
> ファイルの返り値になる（インポートした側が受け取るもの）。
> したがって最終行の行頭バッククォートは、コメントか返り値かの分かれ目にある。
>
> - **コメントを書きたいなら、最終行では閉じてはならない**（閉じなければ必ずコメント）
> - **文字列を返したいなら、名前に束縛してから返す**（`` r : `result` `` の次の行に `r`）
>
> どちらの規則を採っても、最終行のこの一点だけは書き手が決めるしかない——
> 「閉じた裸の文字列」が返り値なのかコメントなのかは、書かれたものからは決まらないためである。
> 上の2つの書き方はどちらの規則でも意図どおりに読まれる。

## 3. インデント内のバッククォート（ドキュメント文字列）

インデント（タブ）の後に `` ` `` が来る場合は、行頭ではないのでコメントにならない。
行頭以外のバッククォートは常に文字列リテラルであり、先読みルールは関与しない。

```text
calc_func : x ?
\t`ドキュメント文字列（タブ後・閉じあり → 文字列として評価されるが捨てられる）`
\tx * 2
```

この文字列は評価されますが戻り値として使われないため、事実上コメントとして機能します。

## 4. 最終行の返値

Sign の実行モデルでは**すべてのファイルは関数**である（`impl/core/execution_model.md` 参照）。

したがって、**ファイルの最終行（最後の非コメント式）がそのファイルの返値**になる。

```text
` greet.sn
name : `World`
`Hello, {name}!`    ← 最終行：このファイルの返値
```

```text
` calc.sn
add : x y ? x + y
mul : x y ? x * y

add 3 4    ← 最終行：7 がこのファイルの返値
```

## 5. 複数行の文字列

Sign の文字列は**シングルライン**が基本。

複数行の文字列を扱いたい場合は、文字列のリストまたは連接演算子（空白）を使う：

```sign
` 複数文字列の組み立て
` リスト構築
lines : `Line 1` `Line 2` `Line 3`

`改行文字自体を文字として扱う
text  : `Line 1` \
 `Line 2`
```

注意点として、この言語にはエスケープシーケンスを用意する必要が無い。
`\`後の任意の1文字が文字として扱われる。

---

## 6. Unicode との関係

文字列は `0u` リテラル（Unicode コードポイント）のシーケンスとして扱える：

```text
` ASCII 文字列
hello : `Hello`

` 個別コードポイントとしてアクセス
h : `hello` ' 0   ` → \h（0u48）
```

## 7. 文法仕様（実装者向けメモ）

- 字句解析レベルでコメント行を削除しても構わない（コメントは Unit を返すのと同じ）
- シンタックスハイライトや Language Server は**「行頭のバッククォートのうち、閉じの直後が後置演算子（`@` `~` `!`）でも空白でもないもの」**をコメント色で表示する
- PEG では**否定先読み**で判定する。走査する文字クラスからバッククォート自身を除くのが要である——PEG の `*` はバックトラックしないので、除かないと走査が行末まで食い尽くし、閉じがそこにあっても見つけられない
- **同じ規則の写しが7本ある。直すときは全部直す：**
  - `alpha/javascript/sign.pegjs`（実装。ここから `parser.js` を生成する）
  - `documents/ja-jp/impl/syntax/grammar.pegjs` / `documents/en-us/impl/syntax/grammar.pegjs`（正式仕様）
  - `documents/ja-jp/guide/string_and_comment.md` / `documents/en-us/guide/string_and_comment.md`（この文書）
  - `tools/vscode/syntaxes/sign.tmLanguage.json` / `tools/emacs/lisp/sign-mode.el`（エディタ支援）

## 設計の意図

- **バッククォートのみで文字列とコメントを兼用** → 予約語や専用引用符を増やさず、記号を最小限に保てる
- **行スコープ** → コンパイラがトークン境界を一行ずつ静的に解析できる
- **コメントは SOL、式になるのは閉じの直後に演算子が来たときだけ** → 視覚的に明確、予約語不要、コメントの中に言語の構文を引用できる
- **最終行返値** → 「ファイル = 関数」の実行モデルと一致
