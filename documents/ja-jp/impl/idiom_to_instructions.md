# 字面と命令の対応——Sign で Sign を書く

Sign の後段を Sign で書くための土台である。

**判定はひとつだけ。ある書き方が正しいのは、それが出す命令が、手で書くつもりだった命令と同じときである。**
書きやすさと機械の良さは別々の話ではない。Sign はアセンブリに近い言い方をするので、同じ意味の綴りが
2つあるなら、命令の少ない方が普通は読みやすい方でもある。以下はその一致を実測で確かめた表である。

本書の数字は **HEAD `04bf32f2`（2026-09-16）** の実測であり、推定はひとつも無い。
アンカー（下の表）だけは、その後に入った「実行時の `__` を連結で畳む」直しの後で測り直してある
——畳む検査のぶん preprocess.sn は 3488 → 3711、lexer.sn は 587 → 602、parser.sn は 993 → 1013。
個々の字面の命令数（§2 以降）は畳みの対象を含まないものが大半で、そちらは 04bf32f2 のままである。

表の中では、改行を ⏎、字下げの TAB を → と書く。

## 1. この書き方でのコンパイラの形

### 1.1 原文は1本の綴りで、位置で持つ

器を切って渡すのではなく、**綴りと添字**を渡す。

```sign
walk : s i n ?
	i = ||s|| : n
	walk s (i + 1) (n + 1)
```

`||s||` はループの中でも **0 命令** である。綴りは `{ptr,len}` で x0/x1 に来ているので、
`i = ||s||` はそのまま `cmp x2, x1` になる。**長さを別の仮引数へ手で持ち上げてはいけない**——
42 命令が 46〜48 命令に増える（綴りによる。実測）。既に x1 に在るものを、もう一度運ぶことになるからである。

器を縮めて歩く形（`cnt (s ' 1~) (n + 1)`）は**黙って誤答する**。空の器は `__` そのものなので、
完全性公理の `cmp x1, #0 / b.eq .Lunit1` が本体より先に立ち、終了の枝に届かない。§5 を見よ。

### 1.2 状態は仮引数の並びである

Sign にループは無い。段を持つのは末尾自己再帰であり、機械の上でそれは `b .Lloop0` になる。
運ぶ状態は仮引数の並びそのものである。

既定引数のブロックは「呼ぶ側が初期値を書かなくてよい」を買える。ただし**ただではない**。

| 書き方 | 命令 | 別形 | フレーム | 1文字あたり（実行） |
|---|---:|---:|---|---:|
| 素の仮引数 `cnt : s i n ?`（呼ぶ側が初期値 `0 0` を書く） | 65 | 121 | 32 バイト | **38** |
| 既定引数で状態を持つ（`i : 0` と `n : 0` を書く） | 80 | 135 | 48 バイト | **45** |

既定の解決は呼ばれた側に在り、`.Lloop0:` は**その上**に置かれる。だから毎周、既定が渡されたかを
問い直す（`movz / cmp / b.ne` ×2 と写し2本）。内側のループでは素の仮引数で書き、既定引数は
外側の入口に置くのがよい。

### 1.3 出来た端から書き出す

器を返すと sret になる。sret 自体は正しく、追記の自己再帰は本物のループになる（`bl` は 0、
確保も段の伸びも1要素あたり 0）。しかし**返す器の上界が書ける形は狭い**。

| 形 | 結果 |
|---|---|
| `(s ' 0) (f (s ' 1~))`（1要素ずつ） | 出る（88 命令、実行 34/要素） |
| `(s ' 0~) (f (s ' 1~))`（1切り出しずつ） | **断られる** |
| 1文字ずつ足して Int の計数で回す | **断られる** |

上界は `konst + Σ coef×‖仮引数‖ + coef×μ‖仮引数‖` としか書けない。桁数が値で決まる 10 進の
書き出しは、この言葉の外側に在る。だから**書き出しは器を返さず、その場で書く**。

```sign
put_str : s i ?
	i >= ||s|| : i
	out # (s ' i) : put_str s (i + 1)
```

書き込みを**枝の条件に置く**のがこの形の要である。`#` の値は書き込み先の番地であって `__` には
ならないので、枝は必ず取られ、枝の値が続きになる。

順に並べるだけなら `seq` が使える。**引数は左から順に評価される**（実測：8引数まで綴りの順に出た）。

```sign
seq8 : a b c d e f g h ? h
```

| 並べ方 | 命令 | `bl` |
|---|---:|---:|
| `seq2` を入れ子（4つ並べる） | 43 | 3 |
| `seq4`（4つ並べる） | 34 | **1** |
| `seq6`（6つ並べる） | 46 | **1** |

n 引数の `seq` を1本用意する方が、入れ子より `bl` が減る。

### 1.4 表は引く。枝で分けない

`match_case` は**直線の鎖**である。枝がいくつあっても、まとめも飛び表も出ない。

| 枝の数 | 命令 | 別形 | 1枝あたり |
|---:|---:|---:|---:|
| 2 | 30 | 48 | — |
| 5 | 54 | 87 | 8 |
| 12 | 110 | 178 | 8 |
| 20 | 174 | 282 | 8 |

実行はさらに素直で、**k 番目の枝に当たるのに `6k + 14`** である（12枝の末尾 86、20枝の末尾 134、実測）。

同じ 12 の分岐を手で書いたもの（どれも同じ値 120 を返すことを確かめてある）：

| | 静的 | 実行（末尾に当たる） |
|---|---:|---:|
| Sign の `match_case` 12 枝 | 110 | **86** |
| 手書きの直線の鎖 | 51 | 27 |
| 手書きの値の表 | 10 | **8** |

対して、名前付きスロットの表は**引くのがほぼ無料**である。

| 引き方 | 静的 | 実行 | 表の大きさに依るか |
|---|---:|---:|---|
| 静的な鍵 ``(infix ' `+`) ' tier`` | 18 | **16** | 依らない（`+` `*` `:` `&&` `%` すべて 16） |
| 実行時の鍵 `f : k ? (infix ' k~) ' tier` | 53 | 91〜383 | **依る**（35 行の線形走査） |

実行時の鍵は綴りの長さで先に落とし、一致の確認は末尾から前へ向かって行う。
`%` で 91、`+` で 154、`:` で 210、表に無い綴り（`><`）で 383。**外れが一番高い。**

だから**綴りが静的に書けるところは必ず静的に書く**。分岐で書くべき所は表で引き、
表で引けない所（レジスタ番号など）は、そもそも表にしない——`x` と 10 進の連結で済む。

### 1.5 失敗は `__`、受けるのは `|`

`__` は呼び出しの鎖を通り抜ける。各段の入口が `movz / cmp / b.eq` の3命令で、本体へ入らずに
`__` を返す。`|` は分岐（csel ではない。右辺を評価しないため）で、**8 命令**である。

ただし**引数として来た `__` は `|` で捕まらない**。完全性公理の見張りが本体より先に立つので、
`|` が捕まえられるのは関数の**中で**生じた `__` だけである。

```sign
c : x ? (b x) | 99
```

`c __` は 99 ではなく `__` を返す（実機・インタプリタとも一致）。

### 1.6 呼ばれない関数は出せない

仮引数の型は呼び出しサイトから決まる。**駆動されていない関数は診断になる。**

```
seq2: 仮引数 b の渡し方が決まりません（直和か族）
```

だから Sign で書く後段の各ファイルは、**自分を使い切る駆動行を持つ**か、上から呼ばれる形で
同じ翻訳単位に入っていなければならない。「まだ使っていないが置いておく」は成立しない。

## 2. 字面 → 機械 → 代金

「命令」はプログラム全体の既定の出力、「別形」は `regAlloc:false`。
**フレームは測っている関数自身の `stp x29, x30` の有無**である（`_sign_main` は呼び出しがあれば必ず取るので、
そちらは数えない）。実行/回 は qemu のトレースから。すべて実測。

### 2.1 束縛と呼び出し

| 字面 | 機械の上で何になるか | 命令 | 別形 | フレーム |
|---|---|---:|---:|---|
| `x : 42` ⏎ `x` | `mov x9,#42 / mov x0,x9 / ret` | 3 | 3 | 無 |
| `x : 6 * 7 + 1` を1回使う | 定数畳み込みは無い。式がそのまま出る | 7 | 31 | 無 |
| 同じ束縛を2回使う | **右辺がもう一度出る**（`mul` が2つ） | 19 | 55 | 無 |
| 同じ束縛を3回使う | 3つ目も出る | 31 | 78 | 無 |
| `x : f 3` を1回使う | `bl f` 1回＋`.Lbind_x` へ `str`。読むたび `adrp / add :lo12: / ldr` の3命令 | 22 | 34 | — |
| 同じ呼び出しの束縛を2回使う | `bl` は1回のまま。`adrp/add/ldr` が2組 | 34 | 48 | — |
| `add : a b ? a + b` ⏎ `add 3 4` | 呼ぶ側は手書きと同一。呼ばれた側は仮引数ごとに見張り3命令 | 18 | 34 | `add` は**無** |
| 既定引数を省く / 渡す | 省いた印は niche。呼ばれた側の本体は**同一** | 28 / 28 | 39 / 41 | 有 |
| `app $add 3 4`（`$` で関数を渡す） | `app` が消え、呼び出しが `bl add` になる | 18 | 34 | `add` は**無** |

**束縛は値ではなく置換である。** 右辺が式なら使うたびに出し直され、代金は使用回数に比例する。
右辺が**呼び出し**のときだけ一度だけ評価され、`.data` のセルに置かれる。

**`blr` はどこにも出ない。** `$` は静的に解決され、直接分岐になる。`app $add 3 4` では
中継の `app` そのものが消えて `bl add` だけが残る。前段3ファイルを通しても `blr` は 0 である。
実行時の関数値が無いことの裏返しでもある（§5.2「関数の番地を器に入れる」）。

### 2.2 比較と分岐

| 字面 | 機械の上で何になるか | 命令 | 別形 | フレーム |
|---|---|---:|---:|---|
| `\0 <= c <= \9`（両端が字面） | `sub x9,x0,#48 / cmp x9,#9`（符号なし幅比較）＋ csel | **22** | 34 | **無** |
| `(\0 <= c) & (c <= \9)` | 比較2本ぶん。単位元の判別（`cmp / ccmp / csel`）も2組 | **40** | 56 | **有** |
| `a <= c <= b`（両端が仮引数） | 幅比較の綴りを失う | 35 | 55 | 有 |
| `n > 3` を値として返す | 前提（左辺）が返る。単位元の判別つき | 20 | 31 | **無** |
| `n > 3` を条件に使う | 同じ7命令を出したあと `cmp / b.eq` で読み直す | 30 | 38 | **有** |
| `(g n) &#124; 0` | `cmp x0,niche / b.ne` の分岐（短絡のため csel ではない） | 48 | 62 | 有 |
| 同じものから `&#124; 0` を外した下敷き | — | 40 | 53 | 有 |
| `__` が3段の呼び出しを通る | 各段 3 命令で素通し。途中は末尾呼び出し | 35 | 56 | 葉は無 |

**連鎖比較と `&` は同じ意味ではない。** 18 命令ちがい、しかも `&` の側だけがフレームを取る。
文字1つごとに払う場所なので、レキサでは必ず連鎖で書く。良い道は**両端が字面のときだけ**通る。

**比較を条件に使うとフレームが生える。** 値の形（20 命令、フレーム無）と条件の形（30 命令、フレーム有）は
同じ7命令を出し、条件の側はそれを `cmp / b.eq` で読み直す。その読み直しのために生じたレジスタの圧が、
枝の結果を呼び出し先保存レジスタへ押し出し、退避のためにフレームが要る。

#### 段の代金——スタックは、この言語では意味論の一部である

Sign にはループが無く再帰しか無いので、**入力の大きさがそのまま段数になる**。命令数の表だけを見ても
「その入力で走るか」は分からない。段の代金は2つの直線で測れた（どちらも傾きは区間によらず一定）。

| 何 | 1つあたり | 例 |
|---|---:|---|
| 非末尾の算術再帰 | **32 B/段** ＋ 48 | 8000 段で 256048 B。256000 B では踏み抜き、256256 B で通る |
| `preprocess.sn`（入力1文字あたり） | **50 B/文字** ＋ 592 | 13471 文字（＝`preprocess.sn` 自身のバイト数）で 674142 B。663552 B では踏み抜き、679936 B で通る |
| 末尾再帰・相互末尾再帰 | **0**（TCO でループになる） | 64KiB のままで 200000 段が通る |

前段4ファイルを**自分と同じ大きさの入力**として通すのに要るスタック（`50n + 592`、LF のバイト数で）：
`preprocess.sn` 13471 → 659KiB、`operator_table.sn` 9703 → 475KiB、`parser.sn` 4852 → 238KiB、
`lexer.sn` 2025 → 100KiB、`emit.sn` 1760 → 87KiB。**自己ホストには最低でも 1MiB 要る。**

50 B/文字 のほとんどは**予約であって書き込みではない**（実測では1文字あたり約 4.7 B しか書かない）。
素の枠はどれも 96 B 以下で、深さは実行時に大きさが決まる `sub sp, sp, xN`（sret の返値スロット）から来る。
**踏み抜きが疎になるのはこのためで、壊れ方が入力の大きさごとにばらばらだったのもこのためである。**

スタックは image の**下**に置いてある（`alpha/javascript/qemu/link.ld`）。

```
0x40000000  _stack_limit ＝ RAM の下端。ここより下は RAM の外
     ↑ sp はここへ向かって下りる
_stack_top ＝ image の基底（既定なら 0x41000000）
     .text / .rodata / .data / .bss
```

踏み抜くと RAM の外へ出て外部アボートになり、`start.s` の例外表が `STKOVFLT` と FAR/ESR/ELR を流して
0.2 秒で抜ける（`-M virt` の 0x40000000 直下は PCIe ECAM の窓で、書き込みは ESR 0x96000050＝外部アボート）。
限界の 128 B には番人を敷いてあり、落ちずに戻ってきた踏み抜きは `STKSMASH` で捕まる。
sp は `_stack_top`（＝image の基底）から**下へしか動かない**ので、**踏み抜きが image へ届くことはない**。
以前はスタックを image の直後に置いて 64KiB しか与えておらず、`preprocess.sn` は
1300 文字で自分の `.rodata` を、1500 文字で自分の `.text` を書き換えながら走っていた——診断は1件も出ず、
1400 文字では入力長を返し、1425 文字では止まらなくなり、2300 文字を超えるとまた全部正しくなった
（行き過ぎて image を飛び越すため）。**「大きい入力が通った」はスタックが足りている証拠にならない。**

大きさは呼ぶ側が決める：`runAsm(asm, { stack, memMB })`。既定は **16MiB**——いま書ける `.sn` のどれに対しても
20 倍以上の余裕がある。置き場所のおかげで大きく取っても代金は番地だけで、実測でも起動時間は変わらない
（既定・64KiB・64MiB のどれでも 0.2 秒台）。image がスタックの上に載るので、RAM に収まらない大きさは
**リンクで落ちる**（`-m` を増やすなら `memMB` も一緒に渡す）。

### 2.4 器と表

| 字面 | 機械の上で何になるか | 命令 | 別形 | フレーム |
|---|---|---:|---:|---|
| `s ' 0`（先頭を添字で） | 添字が字面でも範囲の見張りが全部出る | 24 | 40 | 無 |

## 5. 書いてはいけない形

断られる形と、**黙って誤答する形**を分けて置く。断られる方は安全であり、黙る方が危ない。

### 5.1 黙って誤答する形

| 書いてはいけない | 何が起きるか | 代わりにこう書く |
|---|---|---|
| 器を縮めて歩く<br>`cnt : s n ?` ⏎ →空の綴りと比べる枝 ⏎ →`cnt (s ' 1~) (n + 1)` | **`__` が返る**（実機・インタプリタとも）。空の器は `__` そのものなので完全性公理が本体より先に立ち、終了の枝に届かない。長さを 0 と比べても、`!s` に書き換えても同じ | 添字で歩く（§1.1）。どうしても縮めるなら **1手前で止める**——長さを 1 と比べて `n + 1` を返す（45 命令、正しい） |
| `(s ' 0) == 104`（Char と Int） | 実機は 104、インタプリタは `__`。符号位置が違うときは両方 `__` なので、**真の場合だけ**食い違う | Char どうしを比べる：`(s ' 0) == (t ' 0)`（49 命令、一致） |
| Char と1文字の綴りを比べる | 1要素の器に持ち上がって綴りの比較ループが回る。観測される値も両側で違う | 同上 |
| `f : p i v ? (p + (i * 8)) # v` を layer 1 で | **断られずに出る。** 実機は書き込み、インタプリタは `__`。同じことを1つの式で書けば（`($x + 8) # 7`）門が「`$` が作った番地は算術に使えません」で止める——**門は構文の形しか見ておらず、仮引数を1回挟むと抜ける** | 番地の算術をしない。書き出し先は束縛した定数にする（`out : 0x9000000`、5 命令） |
| 同じ名前を2回定義する | 診断 0。インタプリタは後の定義を採り、機械は同じラベルを2つ出してアセンブラが断る（`symbol 'g' is already defined`）。**3か所で決まって、どこも一致していない** | 名前を重ねない |

### 5.2 断られる形（と、出る綴り）

| 書けない | 出る言葉 | 代わりにこう書く |
|---|---|---|
| 本体の中の局所束縛<br>`f : n ?` ⏎ →`x : n * 2` ⏎ →`x + x` | `まだ出せない識別子です（x）`（インタプリタは黙って `__`）。字下げた `x : …` は枝として読まれる | 既定引数のブロックを let に使う（32 命令）。短い式なら**2回書く方が安い**（19 命令） |
| `a % b` | `まだ出せない式です（mod）`（インタプリタは答える） | `a - ((a / b) * b)`（26 命令。手書きは `sdiv / msub` の 2） |
| Int で回して器を返す<br>「1文字 ＋ 自分を n-1 で呼ぶ」 | `器の構築はまだ出せません（String——…上界は konst + Σ coef×‖仮引数‖ と coef×μ‖仮引数‖ しか書けない）` | 器を返さず、その場で書き出す（§1.3） |
| 1切り出しずつ足す<br>`(s ' 0~) (f (s ' 1~))` | 同上。**1文字ちがうだけで**、`(s ' 0)` なら出る | 1**要素**ずつ足す |
| 一番外で綴りを2つ繋ぐ | `器の構築はまだ出せません（String——…自分のフレームに取る道には走査して写す枝が無い。sret の枝にしかない）` | 関数の中で繋いで返す（そこは出る） |
| 実行時の鍵 **かつ** 実行時の欄<br>`(infix ' k~) ' c~` | `鍵が実行時に決まる引き方は、全スロットが同じ幅でなければ出せません` | 欄は静的に書く。表を作るときは全欄を同じ幅（綴り）で揃える——`asm_…` の表がそうなっている理由 |
| 静的な鍵が外れる<br>``(infix ' `><`) ' tier`` | `構造体に >< というスロットがありません`——**コンパイルエラーであって `__` ではない** | 「その綴りは演算子か」を問うなら**実行時の鍵**で引く。外れは `__` になり `&#124;` で受けられる |
| 綴りの List<br>``regs : [`x0` `x1` `x2`]`` | `器の構築はまだ出せません（String——撒いているので要素数が実行時に決まる…）` | 名前付きスロットにするか、**そもそも表にしない**（`x` と 10 進の連結で足りる） |
| 本体の中の裸の構造体<br>`f : t ?` ⏎ →`kind : 9` ⏎ … | `まだ出せない識別子です（kind）` | 括弧の中のブロックで書く：`f : t ? [` ⏎ →`kind : 9` ⏎ `]`（55 命令、動く） |
| 構造体の項目を1行に並べる<br>`[ kind : k , len : … ]` | `` `名前 : 値` を値の位置に書けません—— `` | 括弧の中を**行**で書く（上と同じ） |
| 書き出しのループを layer 0 で | `layer: 0 では put がフレームを要求します` | layer 1 で書く。1回きりの書き込みなら layer 0 でも出る（5 命令） |
| レンジに終端つきの切り出し<br>`[0 ~ 9] ' [2 ~ 3]` | `終端の有る切り出しを規則に当てる形はまだ出せません（起点はずらせるが、終端を縮める命令が無い）` | 開いた切り出しは出る：`[1 ~ 9] ' 2~`（23 命令） |
| 関数の番地を器に入れる<br>`proc : [$dbl , $tri]` | `アドレスを取れるのはフレームに在るものだけです（dbl）`。4通りの綴りを試したがすべて同じ | 実行時の関数値は無い。分岐は表で**綴りを**引き、綴りから直接呼ぶ |
| 呼ばれない関数を置く | `仮引数 X の渡し方が決まりません（直和か族）` | §1.6 |

## 6. 最初に書く1枚

`alpha/sign/emit.sn`。**診断 0、576 命令、別形 801、`bl` 25、`blr` 0、末尾ループ 3、フレーム 11。**


最後の行は `><` が表に無いことを `|` が受けた結果である。

```sign
`emit.sn — 後段の最初の一枚。綴りを文字として書き出す`

`operator_table.sn`@~

`--- 書き出し先。番地は束縛するだけで、算術はしない ---`

	out # c

	i >= ||s|| : i

	seq2 (put_char 35) (put_dec n)

	(asm_infix_signed ' k~) ' gpr_signed

put_alu : op d n m ?
	seq8 (put_str op 0) (put_char 32) (put_reg d) (put_str `, ` 0) (put_reg n) (put_str `, ` 0) (put_reg m) (put_char 10)
```
