## 1. 規則

### V1 入口
- **文面**
  - 先に `resolve` を通す。読む段の断りはファイルごと止める（R119）。
  - 値は、書いた行の木（`resolve` の `rows`）の項の並びを、左から2つずつ畳んで決める（R118）。
  - 解決器の木と種類は予想で、値を決めない。試験が値と突き合わせるだけに使う。
  - `resolve` に足すのは、書いた行の木 `rows` と、行の木から元のソースの行を引く `lineOf` だけ。
- **出どころ**：R118・R119（片イ、`85decb43`）。U 2026-11-04（§0.1）。

### V2 値
- **文面**
  - 値は次の4つ。
    - Int（64 bit。BigInt で持つ）
    - `_`
    - 並び（2つ以上の値。1つの並びは値そのもの、`[x] ≅ x`）
    - 関数（仮引数が全部裸の名前の関数と、その部分適用・合成）
- **出どころ**：U〔答え〕[2026-10-28 00:0x 438d5b1a]（Int は 64 bit）。`[x] ≅ x` は bialgebra の読み（メモリ）。

### V3 畳みの1歩
- **文面**
  - いちばん上が関数で次が値なら適用、次も関数なら合成（左の関数から実行する）、ほかは積む。
  - 口が埋まった関数の答えは、合成の次の段へ流し、段が尽きた後の答えは並びに積む。
  - 余った実引数は後ろに積む。
  - 値の口に来た `_` は消える。書いた `_`・名前の `_`・計算の `_` のどれでも同じ。いちばん上が値のときに来た `_` も消える（並びの単位）。
  - 未定義の名前は `_`。
- **出どころ**：R11・R35・R40・R47・R120（解決器の予想と同じ規則）。
  - 値の口の `_`：R105・R106・R112、U〔答え〕[2026-10-27 15:5x 58a809c9]「…書いた・名前・計算の _ は値の口でどれも同じ。…」。
  - 未定義の名前：R111。

### V4 評価する所
- **文面**
  - 評価する所では、余った関数は `_`。評価する所は次の所。
    - 行の根
    - 演算子の被演算子
    - 手続きの行
    - 枝の条件と値
    - 本体の返す所
  - 定義の右辺と括りの中は評価する所ではない。並びに1つだけ残った関数は関数のまま、値の上に残った関数は `_`。
  - `,` の辺も左から畳み、`_` は積の単位。
- **出どころ**：R42・R52・R76・R87・R123・R125（関数の `_`）。R61・R121（`,`）。

### V5 算術
- **文面**
  - `+ - * / % ^` は Int の上の演算。`_` は両側の単位（`_ - 2` は 2）。
  - `/` は 0 へ切り捨て、`%` はその余り。
  - 0 で割る・溢れ・負の指数の冪は `_`。
  - 前置 `-` は符号を変える（`-_` は `_`）。当てるのは、芯の中の演算子が算術の範囲の時だけ。渡された仮引数は見ない（`neg : a ? -a` ⏎ `neg (5 > 3)` は -5）。
    - 片1 で通す芯は、字面・`_`・仮引数・未定義の名前（`_`）と、それを算術の中置でつないだ物、それを1つ括った物。
    - 線の外の芯の答えは `_` と information（U〔答え〕10-30 17:58）だが、読む段がまだ線を引かないので、線の外と言い切れない芯（定義の名前・適用・比べ）は V12 のまだで止める。
- **出どころ**：U〔答え〕[2026-10-28 00:0x 438d5b1a]「…Int の割り算は 0 へ切り捨て、0 で割ると Int・UInt は _、…Int の溢れは _、…負の指数の冪と負の階乗は _、Int は 64 bit。」。
  - 両側の単位：U〔答え〕[2026-10-28 00:2x 438d5b1a]（`_ - 2` は 2、`3 / _` は 3、`-_` は `_`）。
  - 前置 `-` の線：U [2026-10-30 14:47]「…中の演算子が算術の範囲になっている場合は、前置-を許容する」、U〔答え〕14:52「通す」（渡された仮引数）。
- 溢れの `_` はその場で生まれて単位で消える（alpha1 の `(MAX+2)+(0-2)` は -2。U 2026-10-27 23:43・U〔答え〕23:51）。

### V6 比べ
- **文面**
  - 中置の `<`・`<=`・`>`・`>=` は、成り立てば左、外れたら `_`。0/1 の例外は無い。
  - どちらかが `_` なら `_`。
  - 括らない3項の連鎖（読む段が通すのは `a < b < c` と `a > b > c` だけ）は、成り立てば真ん中、外れたら `_`。
  - `==` は深く比べて、等しければ左。どちらかが `_` なら `_`。並びの比べは器の片（V12）。
- **出どころ**
  - 成り立てば左：U [2026-10-27 23:01 438d5b1a]、U〔答え〕[23:5x]「…比べは成り立てばいつも左（0 < 5 は 0）。…」。
  - `_` と外れた範囲：U [2026-11-04 159479c9]「x < _ や _ < x は 全部 _ / 外れた範囲も _」。
  - 連鎖：U [2026-10-27 23:33・23:34 438d5b1a]、U〔答え〕[23:36]。
  - `==`：U〔答え〕2026-10-27 23:54。`==` の片側の `_` は R（「全部 _」を `==` にも読んだ）。
  - 点なしの `[<] 1 _ 3` が 1 のままなのは片2 の話（min・max の単位）。

### V7 論理
- **文面**
  - `&` は左が `_` なら右を読まずに `_`、ほかは右。
  - `|` は左が `_` でなければ右を読まずに左、ほかは右。
  - `;` は両側を読み、片方だけが値ならその値、両方とも値か両方とも `_` なら `_`。
  - ほかの演算子は両側を読む。
  - `&`・`|`・`;` は値を見ずに `_` かどうかだけを見るので、並びもそのまま通す。並びを見る値の演算子（算術・比べ・`==`・前置 `-`）に並びを当てる形は器の片（V12）。
- **出どころ**：U〔答え〕2026-10-27 23:38（短絡）、U 2026-10-27 23:56（`;`）。U [2026-10-29 12:52 32fe4b9c]「_ ; 5 = _ 5 = 5 _ = 5 ; _ / さらに、 / _ | 5 = _ 5 = 5 _ = 5 | _」。

### V8 本体
- **文面**
  - 本体は1行か、字下げのブロック。
  - ブロックに枝（`:` の行）が無ければ手続き `l1 & … & ln`。`_` の行で止まり、最後の行の値を返す。
  - 枝が有れば選び。`(c1 & v1) | … | 既定` と同じ答えで、値が `_` の枝は次の枝へ進む。既定の行は最後に1つだけ置ける。
- **出どころ**：R76（手続き）。U〔答え〕2026-10-29 12:46、U [2026-10-29 12:52 32fe4b9c] と U〔答え〕「合ってる」（枝の値の `_` は次へ進む）。

### V9 定義
- **文面**
  - ファイルのいちばん外の定義は順序に依らない（使う行が定義の前でもよい）。同じ名前の2つ目は読む段が断る（`name-duplicate`）。右辺が書いた `_` 1つの定義は書かなかったことと同じ。
  - 定義は自分の行で1回走らせて覚える。先に引かれたら、その時に1回走る。だから引かれない定義も走り、その中の「まだ」は止まり、知らせも出る。
  - 深さの上限（V10）で欠けた値は覚えない。後で引かれたら走り直す（覚えると、後の行の値が前の行の深さで変わる）。
  - 定義でない行の値はファイルでは捨てる。試験の口（`interpret` の `values`）は行ごとに返す。
- **出どころ**：U〔答え〕2026-10-31「引かれた時」（自分の行で1回、先に引かれたらその時に1回）。順序に依らない：2026-09-19 の決着（メモリ）。U〔答え〕2026-10-30 15:23（行の値を捨てる）。R113（`x : _`）。

### V10 資源
- **文面**
  - 末尾の呼び出しはループで回す（トランポリン）。返す所は綴りでなく意味で決める：行の答えが最後の呼び出しの答えそのものなら末尾。
    - 後ろの項が全部 `_` の呼び出し（`f x _`）、返す所に置いた括りの中（`(f x)`）、`&`・`|` の右、`,` の空の辺の隣も返す所。
  - 評価の入れ子（末尾でない呼び出し・項・行）の深さを数え、上限で `_` と information。JS のスタックの溢れに頼らない。
  - 呼び出しは関数と実引数で決まる（値は書き換えず、同じ呼び出しは同じ答え）。だから次の2つは止まらない輪で、回さずに V12 のまだで止める。
    - 末尾のループが前に通った状態へ戻る（アイドル。問12「アイドルでいい」の `_ _ = _` の永久ループ。互いに呼ぶ物・行き来する物も。Brent の方法で見つける）。
    - 答えを出している途中の呼び出しを、同じ実引数でもう一度呼ぶ。必ず読む所なら問10 で読む段が断る輪（読む段にまだ無い）、枝の中なら同じ引数の輪で眠る（問12、戻8「眠るまま」）。どちらも解釈器にまだ無い。
  - 同じ状態へ戻らない止まらない輪（`up : x ? up (x + 1)`）は、1行（ファイルのいちばん外の行）の計算の量の上限で止める。解釈器の都合なので `_` にせず、重かった行を名指しして止める（reason は `interpret-work-limit`）。量は行ごとに数え直す（問16「行は別々」）。
- **出どころ**：U 2026-10-27 23:43（資源は `_` と知らせ）。U〔答え〕2026-11-01 問10「必ず読む輪だけ断る」・問12「アイドルでいい」・問16「行は別々」。
- **上限の値（実装の都合、R）**
  - 入れ子の深さ：1200。
    - 呼び出しの深さだけを数えると、1段の中の括りと中置の分だけ JS のスタックが伸び、Node の既定のスタックで 1000 段に届く前に溢れた。
    - 既定のスタックで溢れる手前の入れ子は、本体の形で 2381〜3456（2026-11-04 に測った。手続きの本体がいちばん浅い）。その最小のほぼ半分に置いた。
    - 1200 は、`1 + (deep (n - 1))` の形で約 240 段の再帰にあたる。
  - 1行の計算の量：入れ子に入った回数で 2000 万回（この機械で数秒）。`interpret(source, { workLimit })` で変えられる（試験が小さくして確かめる）。

### V11 知らせ
- **文面**
  - 次の所で `_` が生まれたら、生まれた行に information を出す。同じ理由と行の組は1回だけ。

    | 理由 | 所 |
    |---|---|
    | `zero-division` | 0 で割った |
    | `int-overflow` | Int（64 bit）の溢れ |
    | `no-operation` | 当たる演算が無い（負の指数の冪） |
    | `resource-depth` | 入れ子の深さの上限 |

  - 計算の `_` が口をずらす所は知らせない。
  - 関数が `_` になる所は、読む段の知らせ（`leftover-lambda`・`bare-function-return`）のままで、値の段では足さない。
  - 行は、関数の本体の中なら本体の行。深さの上限は、入れなかった所の行。
- **出どころ**：U〔答え〕2026-10-27 23:41、U 2026-10-30 18:00（出た所の information）。U〔答え〕2026-10-27 23:04（ずれは知らせない）。

## 2. 実装で決めた細かい所（R）

利用者の答えが直接言っていない所。法則と V1〜V11 から1歩で出ると読んだ物。

- 本体が2つ以上の値を返したら、並び1つ。
  - 根では `pp 3` は `3 3`、合成の最後の段なら `inc pp 3` は `4 4`。
  - 並びを次の段の口へ渡す形は、器の片でまだ。
- 口が余る `,` の辺は関数が `_`。
  - `f3 1 , 2` は 2、`f3 1 , 2 , 3` は `2 3`。
  - 問4 の答え「同じ」の線で読んだ物。
- 末尾呼び出しにするのは、返す所で、並びを空にする最後の段の呼び出しだけ（V10）。
  - 呼ばずに取っておき、後ろの項が全部 `_` ならそれを返す。`_` でない項が来たら呼んで畳みを続ける（答えは同じで、後ろの項を読む順だけが先になる）。
  - 合成の途中の段・値の上の関数・`,` の空でない辺は末尾にしない。
  - 値は同じ（試験の法則。深さの上限を越える n でも比べる）。
- `,` の書いた `_` の辺は無いのと同じで、隣の辺は行の置かれた所のまま（R61 と `[x] ≅ x` から1歩）。
  - `w : inc , _` は inc、`(inc , _) 5` は 6、`(_ , double) 5` は 10。
  - 計算で `_` になった辺の隣は、R123 のとおり評価する所（関数は `_`）。

## 3. 試験
